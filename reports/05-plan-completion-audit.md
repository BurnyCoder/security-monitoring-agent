# Approved-plan completion audit

Author: Libor Burian. Audit date: 22 October 2026. This is a requirement-by-requirement engineering check of the approved implementation plan, initiated after the first merged release. It supplements the earlier validation records; it is not another model-quality experiment.

## Method and acceptance criteria

Compare each requirement with shipped code, tests, local runtime state, and the existing live transcripts. Classify implemented behavior separately from observed live validation. A missing feature, contradicted claim, or failing requirement-specific assertion prevents an unqualified completion claim. Use focused synthetic regressions for newly discovered boundary cases, then run the complete test suite. Do not treat a partial investigation as a fully successful detection result.

## Corrections found by this audit

1. A scan with recognized coverage/validation gaps could still advance the research checkpoint when a web event was present. The checkpoint must remain at the last completed scan so an incomplete interval is retried within the configured overlap/news window.
2. A finding using a CVE alias introduced by an advisory in the same response could be rejected before that alias reached storage. Validation must resolve an unambiguous current-response alias without merging notices that cover multiple CVEs.
3. Changing only the agent timeout in Windows task mode did not refresh the task's derived execution limit. Settings reconciliation must include that timeout.
4. A fresh chat could be saved without a resumable session ID, or a resumed response could replace its session with a different reported ID. The runner must reject these protocol failures while retaining an explicitly requested session when the CLI omits unchanged metadata.
5. The news cutoff compared only calendar dates, so a timestamped disclosure older than 24 hours could appear under **Last 24 hours**. Timestamped sources need an exact aware-time comparison; sources providing only dates need an explicitly documented calendar-day policy.

These are software boundary corrections, not new detections or new model experiments. Their raw provider transcripts remain unchanged. The local legacy research checkpoint was removed at 20:18:14 UTC, with a review event appended to the relevant run, because both recorded scans are partial and no completed scan established a valid checkpoint. Existing findings, settings, and timer cadence were retained.

## Observed audit checks

- The pre-change suite passed: 88 tests in 8.72 seconds. Targeted regressions then reproduced the checkpoint, alias, timeout, session-identity, and exact-time cutoff defects before their fixes.
- The final full suite passed: **117 tests in 10.67 seconds** using `.venv/Scripts/python.exe -m pytest -q`. This includes parameterized cases, not 117 independent statistical observations. All six browser modules parsed and linked; `git diff --check` passed.
- Two real scheduler-loop fixtures simulate eight missed hours and a manual request winning at the lock boundary. Both produce exactly one completed synthetic investigation across two loop turns; they use real file locks and storage, with the research phase and periodic wait replaced.
- HTTPX transport fixtures verify CISA primary failure followed by official-mirror success, and total failure reported as incomplete coverage. WSL project fixtures verify literal distribution/path arguments and separate same-package occurrences across two roots.
- Canonical-URL advisory identity is explicit in the scan prompt and storage regression. This uses an exact supplied identity; it does not infer equivalence from shared citation URLs.
- All seven earlier live provider transcripts still matched SQLite event text during the provider audit. No new paid model scan or chat was needed for these protocol/control regressions.
- The updated native server restarted successfully with existing evidence retained. The live status API reported automatic hourly scanning enabled, no active investigation, and the same next scan time. A one-day news request returned three advisories while the saved news window remained seven days. The browser's 24-hour selector replaced the older cards with those recent articles; restoring seven days restored the earlier cards. No new browser errors were recorded after the restart.
- Git inspection confirmed `.env`, runtime data, raw logs, downloaded tools and the local environment remain untracked. The initial feature PR and its main-branch Windows CI had already succeeded.

## Remaining validation limits

Optional Windows login/reboot behavior, extended unattended uptime, a live WSL project-root scan, and independent system-clipboard contents have not been demonstrated. The corresponding implementation and bounded tests are present. The plan did not request automatic remediation, exhaustive vulnerability detection, a labeled accuracy benchmark, model training, or publication of raw device evidence. No such claims are made.
